## 它是什么

「旧手机出码、新手机扫码」把整份备份搬过去。两条路自动挑：

- **内联码**：备份 → deflate → base64 → 前缀 `CB2:` → 直接塞进二维码里（不联网）
- **局域网直传**：旧手机起一个一次性小 HTTP 服务，二维码里放 `http://<局域网地址>:<端口>/cb`

双端都写过：安卓 `QrTransfer.kt` + `QrScanActivity.kt`（照着兽频道那张扫一扫截图自绘的界面），
iOS `Sources/QrTransfer.swift`（`NWListener` + AVFoundation + CoreImage）。

## 为什么撤

不是写不出来 —— 安卓那边已经跑通出过包（3.6.0 / code 65）。撤的原因是按**代价**算不划算：

1. **它会砸掉这个 App 最值钱的那张牌。** 全 App 的叙事是「不联网、不要权限、数据只在你手机里」，
   隐私政策就靠这句立住。为了一个功能加**相机权限**，等于主动破一次例 ——
   用户看到记账 App 要相机，第一反应不是"方便"，是"记账要相机干嘛"。
2. **使用频率对不上成本。** 换手机一年一次；而「分享备份 / 从文件夹恢复」那条路早就有，
   慢三分钟，但不用付上面那个代价。
3. **它不是核心动作。** 兽频道要扫码，因为它的产品本身就是「人和人交换」；
   这个 App 是「你自己的账本」，交换是边缘需求。

**逸风 2026-10-07 拍板：双端都撤。**（中途有过"撤了又装回"，最后定的还是撤。）

一个提交塞了两个不相干的功能，回退就会连坐。
